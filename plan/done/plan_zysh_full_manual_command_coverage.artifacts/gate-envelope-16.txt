1. Scope & Implementation Overview
------------------------------------------------------------------------------
Envelope 16 upgrades the clearance client daemon (`client/netmon-ai-client.c`)
from a naive 300-second idle countdown to an active Anchor Process Liveness Watchdog:

1. Anchor Process Liveness & Anti-Crash Watchdog:
   - `get_anchor_proc_info(anchor, &state, &starttime)`:
     Reads `/proc/<anchor>/stat`, extracts process state (field 3) and starttime
     clock ticks (field 22).
   - `is_anchor_alive(anchor, expected_starttime)`:
     * Asserts process existence in `/proc/<anchor>/stat`.
     * Rejects Zombie (`'Z'`) and Dead (`'X'`) processes.
     * Prevents PID recycling collisions by validating that `starttime` matches
       the original timestamp recorded when the daemon launched.
   - Polling interval decreased from 10s to 5s.
   - Teardown SLA: If the anchor process terminates or crashes, the daemon detects
     death within 5 seconds, transmits `CLOSE` over TCP, unlinks the local domain
     socket `/tmp/netmon-ai-<anchor>.sock`, and exits cleanly.

2. Indefinite Grant Session Retention:
   - For approved indefinite grants (`grant_seconds == 0`), the session remains
     permanently active as long as the spawning anchor process is alive.
   - For bounded grants (`grant_seconds > 0`), the server-assigned deadline is
     enforced.
   - Ungranted connections retain a 300-second inactivity watchdog to avoid orphaned
     unapproved handshakes.

3. Wire Protocol Parsing Correction:
   - Resolved critical wire protocol bug where `GRANTED <connId> <seconds>` caused
     the single-digit connection ID to be parsed as the expiration duration,
     leading indefinite grants (`0`) to expire prematurely in `connId` seconds.
   - Both two-token (`GRANTED <connId> <seconds>`) and single-token (`GRANTED <seconds>`)
     formats are now parsed with 100% precision.
